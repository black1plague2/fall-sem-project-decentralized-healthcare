How it works

Six real steps.

Not a demo timer. These are the actual operations performed by the healthcare vault architecture.

01 / ENCRYPT
Encrypt client-side
A fresh 256-bit key is generated per file and used for AES-256-GCM authenticated encryption.
02 / IPFS
Pin to IPFS
The encrypted package is content-addressed and pinned to IPFS. Plaintext never reaches the storage layer.
03 / KEY WRAP
Wrap the key per actor
RSA-OAEP wrapping creates an independently protected copy of the file key for every authorized actor.
04 / HYDRA
Anchor on Hydra L2
Permission state is proposed to the Hydra Layer-2 head for rapid off-chain permission checks.
05 / VERIFY
Verify on request
Requests move through Hydra L2 → Aiken L1 → Midnight ZK → Blockfrost L1.
06 / REVOKE
Revoke rotates the key
Revocation triggers re-encryption under a new CEK, invalidating the previously distributed key material.

Architecture

Four layers.
Increasing authority.

The architecture combines rapid off-chain verification with progressively authoritative blockchain and ZK layers.

Hydra L2
Off-chain state channel designed for extremely low-latency permission checks.
5–15ms target live
Aiken L1
Plutus V3 smart-contract layer enforcing owner-controlled permission operations.
~2s L1
Midnight ZK
Zero-knowledge verification allows permission proofs without exposing unnecessary information.
800–1200ms ZK
Blockfrost L1
Public Cardano blockchain query acting as the final authoritative fallback.
500–2000ms L1
